# Протокол Toyota OBD-1 у CarTester — результати reverse engineering

Джерело: `CarTester.exe` (Delphi, стиснений UPX 1.25 / NRV2D). Розпаковано власним декомпресором,
дизасембльовано `dumpbin`. Адреси нижче — у розпакованому образі (ImageBase 0x400000).

## Фізичний рівень

- Сигнал з діагностичного виходу ECU подається на лінію **DSR** COM-порту (кабель: два дроти й конденсатор).
- Потік читання (`0x484A74`): `SetCommMask(EV_DSR)` → `WaitCommEvent` → `GetCommModemStatus` (маска `MS_DSR_ON`),
  час між подіями міряє `QueryPerformanceCounter`. Пріоритет потоку `THREAD_PRIORITY_TIME_CRITICAL`.
- Рівень відрізка: DSR був ON → 1, OFF → 0. Опція «інверсія кабелю» його інвертує.
- Тривалість переводиться в біти: `round(мс / 8.2)`. **1 біт = 8.2 мс (≈122 біт/с).**
- Порт відкривається з 9600 8N1, але UART не використовується — лише лінія стану.

## Кадр

```
пауза (1)  ≥ 16 біт
заголовок  15 біт: 0 | 12 біт ID | 1 1
байт k     11 біт: 0 | d0 d1 … d7 (LSB першим) | 1 1        k = 1…12
```
Повний цикл = 15 + 12×11 + 16 = 163 біти (≈1.34 с) — саме цей поріг (`0xA3`) стоїть у потоці читання.

Декодер оригіналу (обробник повідомлення `0x455`, `0x4A5448`) розбирає **рівно 12 байтів**. Якщо ECU передає
довший кадр, решта відкидається. JZ Monitor визначає кінець кадру за паузою і зберігає всі байти.

## Формули (функція MemoDraw, `0x4A785C`)

| Байт | Параметр | Формула | Налаштування (`CarTester.ini`) |
|---|---|---|---|
| 1 | Час впорскування, мс | x × 0.125 | |
| 2 | Кут випередження, ° | x × 0.47 − 30 | |
| 3 | Клапан ХХ (ISCV) | KHH=1: x/255×100 %; KHH=2: x кроків (повний хід 125); KHH=0: не показується | KHH |
| 4 | Оберти, об/хв | x × 25 | |
| 5 | Повітря | 1: MAP x×0.6515 кПа; 2: x×4.886 мм рт.ст.; 3: MAP-T x×0.97 кПа; 4: x×7.732 мм рт.ст.; 5: MAF x×2 г/с; 6: VAF x/255×5 В; 7 (лише JZ Monitor): наддув (x×0.97 − 101.325)/100 бар | Vozduh |
| 6 | Температура ОР, °C | кусково-лінійна таблиця (10 відрізків), t = x або 255−x | Temperature |
| 7 | Дросель | DZ=1: x/2 °; DZ=2: x/1.8 % | DZ |
| 8 | Швидкість, км/год | x (CarTester); JZ Monitor ділить на калібрувальний коефіцієнт, за замовчуванням 3.4 — див. нижче | |
| 9, 10 | Корекція / λ (лівий, правий) | Korr=1: x×5/256 В; Korr=2: x×20/128 − 20 % | Korr |
| 11 | Біти: 0 збагачення після пуску, 1 на прогріві, 4 детонація, 5 зворотний зв'язок, 6 додаткове збагачення | | |
| 12 | Біти: 0 стартер, 1 концевик ХХ, 2 кондиціонер, 3 P/N, 4/5 лямбда (Rich/Lean), 7 TE1→E1 | | |

Температура ОР (t — сире значення з урахуванням інверсії):

| t | °C |
|---|---|
| < 15 | (t−5)×2 − 60 |
| 15…38 | (t−15)×0.83 − 40 |
| 39…81 | (t−39)×0.47 − 20 |
| 82…134 | (t−82)×0.38 |
| 135…179 | (t−135)×0.44 + 20 |
| 180…209 | (t−180)×0.67 + 40 |
| 210…227 | (t−210)×1.11 + 60 |
| 228…236 | (t−228)×2.11 + 80 |
| 237…242 | (t−237)×3.83 + 99 |
| ≥ 243 | (t−243)×9.8 + 122 |

Перевірено на незалежно відкаліброваних точках (2JZ-GTE): кут raw 85 → 10.0°, ОР raw 113 → 11.8 °C, raw 226 → 77.8 °C.

Витрата палива: `л/год = B1 × B4 × PrFors × KolFors × ChastFors × 6.25e-6`; `л/100км = л/год × 100 / B8`.
У CarTester `PrFors` — «Performance of injector, gr/15sec», `KolFors` — кількість форсунок, `ChastFors` —
впорсків за 2 оберти колінвалу. Грами в оригіналі фактично рахуються як мілілітри, тож `PrFors = cc/min ÷ 4`.
JZ Monitor приймає продуктивність у cc/min (за замовчуванням 440 — штатні форсунки JDM 2JZ-GTE non-VVTi; US — 550)
і рахує `B1 × B4 × cc/min × к-сть × впорсків × 1.5625e-6` — те саме число, що й оригінал. Затримка відкриття
форсунок не враховується, тож це оцінка.

## Що оригінал не показував

- **Біти 11.2, 11.3, 11.7, 12.6** — приймаються і пишуться у `.ctr`, але на екрані не відображаються.
- **ID кадру** (12 біт заголовка) — показується лише як рядок біт.
- **Байти після 12-го** — відкидаються ще в декодері.
- Байти 3, 5, 7, 9, 10 при режимі 0 у налаштуваннях не показуються зовсім.

JZ Monitor показує все це (жовті рядки — те, чого оригінал не виводив).

## Що показали реальні логи (Toyota Chaser 1997, 2JZ-GTE non-VVTi, A340H)

9 файлів у `../Chaser logs/` (листопад 2026), 8624 кадри:

- Біти **11.2, 11.3, 11.7, 12.6 — завжди 0**. На цьому ECU вони нічого не несуть, тож оригінал, ховаючи їх, нічого не втрачав.
- **Байт 10 завжди 0** (правий ряд циліндрів буває лише у V6). **Байт 9** приймає тільки 0 або 128 — фактично прапорець, а не напруга.
- **ID** = `100011100010` у 8604 кадрах. Ще 20 кадрів мають інший ID — це, ймовірно, бітові помилки, які пройшли перевірку оригіналу (вона контролює лише старт- і стоп-біти).
- **ISCV (байт 3) не перевищує 125** — повний хід крокового клапана ХХ; шкалу в UI рахуємо від 125.
- **Швидкість (байт 8) на еталонному Chaser треба ділити на 3.4** — підібрано власником за реальною
  швидкістю. Ймовірна причина — свап: ECU 2JZ-GTE розрахований на інший датчик швидкості. Коефіцієнт
  налаштовується в Setup → Speed ÷. Той «максимум 254» з логів = ~75 км/год.
- Шкали плиток у UI (під 2JZ-GTE): RPM 0–8000, MAP −1…+1.5 bar, кут −10…50°, впорскування 0–20 мс, ISCV 0–125. Решта — від сирого байта.
- Діапазони байтів 1–8 правдоподібні: оберти до 110×25 = 2750, MAP 15…115, ОР 86…234.
- Чи передає ECU **байти після 12-го**, з `.ctr` дізнатися неможливо — оригінал відкидав їх до запису. Потрібне живе читання JZ Monitor (стрічка «Прийняті кадри» показує довжину кадру).
- `CtrFormat` читає всі 9 файлів, а збереження дає **побайтово ідентичний** файл.

## V6

Байт 10 і біт 12.5 стосуються правого ряду циліндрів V6. JZ Monitor їх не декодує й не показує
(цільовий двигун рядний; на 2JZ-GTE вони завжди 0). Сирий байт 10 лишається в hex-дампі кадру,
і в CSV.

## Формат .ctr (CarTester 1.0.0.3) — формат записів JZ Monitor

Текст cp1251, CRLF.
```
File for CarTester 1.0.0.3
<кількість кадрів>
на кадр — 40 рядків + час:
  0..9    байти 1..10
  10      службове (оригінал пише зі зсувом на 1 — останній біт ID попереднього кадру)
  11..22  12 біт ID
  23..30  біти 0..7 байта 11
  31..38  біти 0..7 байта 12
  39      мітка кадру
  H:mm:ss
75 рядків   три списки еталонних кадрів (№1–№3) по 25, впереміш
10 рядків   запам'ятовані номери кадрів (кнопки внизу вікна), "0" — порожньо
N−1, N рядків   перше Memo (коментарі)
N−1, N рядків   друге Memo
9 рядків    опис авто: марка, двигун, КПП, рік, пробіг, тип двигуна, циліндри, тип КПП, привід
```
Байти 13+ у цей формат не вміщуються — для них є експорт CSV.
