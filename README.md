# JZ-Monitor

Live data testing for pre-OBD2 JZ GTE engines.

**JZ Monitor** — Windows-застосунок (WPF, .NET 10) для читання потоку даних ECU Toyota OBD-1
(сімейство JZ: 1JZ-GTE, 2JZ-GTE та ін.) через COM-порт. Замінює стару програму **CarTester**:
протокол, формули та формат файлів `.ctr` відновлено з неї методом reverse engineering
(див. [`docs/PROTOCOL.md`](docs/PROTOCOL.md)).

Перевірено на записах з Toyota Chaser 1997, 2JZ-GTE non-VVTi, A340H.

## Можливості

- Читання сигналу ECU з лінії **DSR** COM-порту — той самий простий кабель, що й для
  CarTester. Інверсія сигналу, DTR/RTS для живлення адаптерів.
- Декодування кадрів **будь-якої довжини**. CarTester брав рівно 12 байтів і відкидав решту;
  JZ Monitor показує всі байти, а також біти й значення, які оригінал ховав (виділені жовтим).
- Параметри з формулами CarTester: час впорскування, кут випередження, клапан ХХ, оберти,
  MAP/MAF/VAF, температура ОР, дросель, швидкість, λ/корекція, 16 бітів стану, витрата палива.
  Режими датчиків як у CarTester, можна імпортувати з `CarTester.ini`.
- Записи у форматі CarTester **`.ctr`** — відкриваються в обох програмах (побайтово сумісно
  з CarTester 1.0.0.3). Опис автомобіля, нотатки, мітки кадрів. Файл можна відкрити й з
  командного рядка: `JzMonitor.exe запис.ctr`.
- Мінімальні й максимальні значення параметрів за сесію — на плитках і в таблиці (колонки MIN / MAX).
- Витрата палива за поїздку: літри, кілометри, середня л/100км і час роботи двигуна — накопичуються
  до поточного кадру (оцінка за часом впорскування; паузи в записі довші за 5 с не рахуються).
- Експорт у CSV для Excel (усі байти, біти та розраховані значення).
- Графік вибраних параметрів, перегляд записаних кадрів, стрічка сирих кадрів у hex.
- Контроль якості сигналу: виміряна тривалість біта і відхилення фронтів.
- Світлий інтерфейс у стилі приладової панелі: плитки основних параметрів, індикатори бітів
  стану ECU, графік з програвачем кадрів.
- Запис сирих фронтів сигналу у файл і повторний прогін через декодер — для дослідження
  невідомих варіантів протоколу.

## Протокол коротко

| | |
|---|---|
| Фізичний рівень | рівень діагностичного виходу ECU → лінія DSR COM-порту, тривалість рівнів через `QueryPerformanceCounter` |
| Біт | 8.2 мс (≈122 біт/с) |
| Кадр | пауза ≥ 16 біт · заголовок 15 біт (0, 12 біт ID, 1 1) · байти по 11 біт (0, 8 біт LSB першим, 1 1) |
| Байти 1–9 | впорскування, кут, ХХ, оберти, повітря, ОР, дросель, швидкість, λ (байт 10 — правий ряд V6, не декодується) |
| Байти 11–12 | біти стану (збагачення, детонація, зворотний зв'язок, стартер, IDL, A/C, P/N, лямбда, TE1) |

Повний опис, формули, формат `.ctr` — у [`docs/PROTOCOL.md`](docs/PROTOCOL.md).

## Вимоги

- Windows 10/11
- [.NET 10 SDK](https://dotnet.microsoft.com/download) (для збирання) або .NET 10 Desktop Runtime (для запуску)
- COM-порт (вбудований або USB-адаптер з лініями стану модему) і кабель до діагностичного роз'єму

## Збирання і запуск

```bash
dotnet build JzMonitor.slnx
dotnet run --project src/JzMonitor
dotnet test JzMonitor.slnx
```

## Використання

1. Під'єднайте кабель до діагностичного роз'єму й COM-порту, увімкніть запалювання.
2. Виберіть **PORT** і натисніть **Connect**. Індикатор **LIVE** означає, що кадри приймаються без помилок.
3. Якщо кадрів немає (**NO SIGNAL**), перевірте підключення кабелю й чи увімкнене запалювання.
4. Позначте параметри (галочка на плитці або в таблиці **Parameters**), щоб бачити їх на графіку **TREND**.
   По графіку можна рухатись мишею: натиснути й тягнути (за краєм — прокрутка далі по запису),
   коліщатко — на кадр (з Shift — на 10), клавіші ← → / PageUp PageDown / Home End.
5. **Save** зберігає запис у `.ctr` (відкривається і в CarTester); **CSV** — для Excel, з усіма
   байтами кадру.

Режими датчиків налаштовані під 2JZ-GTE (MAP у bar наддуву, ISCV у кроках, дросель у %, пряма шкала ОР)
і в інтерфейсі не змінюються. Продуктивність форсунок — на вкладці **Setup**. Інші режими можна
підтягнути з **Setup → Import CarTester.ini** або змінити у `JzMonitor.settings.json` поруч з exe.

## Структура

```
src/JzMonitor/          застосунок WPF (без NuGet-залежностей)
  Protocol/             читання COM-порту, збирання кадрів, формули
  Recording/            формат .ctr, експорт CSV, журнал фронтів
  ViewModels/ Controls/ Themes/  інтерфейс
tests/JzMonitor.Tests/  xUnit-тести декодера і форматів
docs/PROTOCOL.md        протокол, формули, формати файлів, що показали реальні логи
tools/re/               інструменти reverse engineering CarTester (розпакування UPX, дизасемблювання)
.claude/, CLAUDE.md     правила й навички для Claude Code
```

## Застереження

Проєкт не пов'язаний з Toyota чи авторами CarTester. Бінарні файли CarTester до репозиторію не
входять. Значення параметрів орієнтовні й перевірені на одному автомобілі; використовуйте на
власний ризик.
